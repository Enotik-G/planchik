# Auth Service (репозиторий `planner`)

## ⚠️ Главное правило: это обучение, а не вайбкодинг

**Код пишет пользователь. Claude объясняет доступным языком и проверяет результат.**

Пользователь осознанно учится Java/Spring и не хочет получать готовые файлы. Claude:

- объясняет, **что** делаем и **зачем**, разбирает концепции простым языком;
- даёт критерии и образец на постороннем примере — но не готовое решение задачи;
- ставит задачу и ждёт, пока пользователь напишет код сам;
- потом проверяет, запускает, разбирает ошибки вместе с ним;
- пишет код сам только когда об этом прямо попросили.

Двигаемся **маленькими шагами, по одной задаче за раз**. Не убегать вперёд и не делать несколько шагов в одном сообщении.

Архитектурный документ в `docs/` написан под вайбкодинг («одна задача = одна сессия в Claude Code») — **в этой части он не указ**, работаем как описано выше.

## Что это за проект

Это **Auth Service** — единый OpenID-провайдер колледжа (SSO для планировщика, meet, соцсети, доски, заметок). Несмотря на имя репозитория, **сам планировщик здесь не пишется**: его делает отдельная команда на Python, и он только проверяет выданные JWT по JWKS.

Ключевая идея архитектуры: Auth выдаёт короткоживущий JWT (10 мин), остальные сервисы проверяют подпись локально и **не ходят в Auth на каждый запрос**.

## Подводные камни (уже наступали)

- **Postgres 18 сменил расположение данных.** Том монтируется в `/var/lib/postgresql`, **не** в `/var/lib/postgresql/data`. Внутри Postgres сам делает подпапку `18/docker`. Со старым путём контейнер отказывается стартовать.
- **Группа `docker` применяется только при новом входе в систему.** Причём в GNOME недостаточно перелогиниться: `gnome-terminal-server` наследует группы от `systemd --user`, который переживает выход. Нужна полная перезагрузка (или `newgrp docker` — но только для одного окна).
- **Системный PostgreSQL 17 был отключён** (`sudo systemctl disable --now postgresql`), он занимал порт 5432. Данные его целы в `/var/lib/postgresql/17/main`.
- **Настройка новой машины:** нужны JDK 25 (`openjdk-25-jdk`), `docker.io`, `docker-compose`, и пользователь в группе `docker`.

## Работа с БД

Схемой управляет **только Liquibase**. `spring.jpa.hibernate.ddl-auto=validate` — Hibernate ничего не создаёт и не правит, только сверяет `@Entity` со схемой при старте. Значения `update`, `create`, `create-drop` использовать **нельзя**: получатся два хозяина у одной схемы.

### Структура миграций

```
src/main/resources/db/changelog/
├── db.changelog-master.yaml      # только include'ы, путь от корня classpath
└── changes/
    └── 001-create-users.sql      # сами миграции — на SQL
```

Master — в YAML (Spring Boot ищет именно этот путь по умолчанию). Сами миграции — **на чистом SQL**, а не в абстракциях Liquibase: проект навсегда на Postgres, а нужны `jsonb`, `uuidv7()`, частичные индексы — в YAML это не выразить.

Формат SQL-файла:

```sql
--liquibase formatted sql

--changeset enotik:001-create-users
CREATE TABLE ...;
```

### Железное правило

**Применённый changeset не правят никогда.** Liquibase хранит его контрольную сумму в `databasechangelog`; при расхождении приложение откажется стартовать. Нужна правка — новый changeset.

Если changeset **упал** — он выполняется в транзакции, откатывается целиком и в журнал не попадает. Можно спокойно исправить файл и запустить заново.

### Соглашения по схеме

- Первичные ключи — `uuid` с `DEFAULT uuidv7()` (нативная функция Postgres 18: индекс не фрагментируется, в отличие от случайного v4).
- Время — **только `timestamptz`**, никогда `timestamp`.
- Перечисления — `varchar` + именованный `CHECK`, **не** нативный `ENUM` (из ENUM невозможно удалить значение).
- Все ограничения именуем: `CONSTRAINT users_status_check CHECK (...)`.
- `NOT NULL` по умолчанию; `NULL` разрешаем только там, где есть легальное состояние «значения нет».
